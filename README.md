# SEC: Sharded Elimination and Combining for Highly-Efficient Concurrent Stacks

This microbenchmark builds upon the [setbench](https://gitlab.com/trbot86/setbench) framework to test and evaluate concurrent stack algorithms. Specifically, this artifact supports the evaluation of **SEC** (Sharded Elimination and Combining), alongside the state-of-the-art competitors considered in the paper submitted to **PPOPP26**.

The following algorithms are evaluated:

- **SEC** (Sharded Elimination and Combining)
- **Timestamp Stack** (TSI)
- **Treiber Stack** (TRB)
- **Combining Stack** (CC)
- **Flat Combining Stack** (FC)
- **Elimination Backoff Stack** (EBF)

We have uploaded the artifact on ZENODO at: [10.5281/zenodo.17705812](https://zenodo.org/records/18077140)

## Repository structure (high level)

This artifact is organized as follows:

- `ds/` : Stack implementations (one folder per algorithm)
  - `ds/stacks_SEC/` : SEC (our stack implementation)
  - `ds/stacks_TRB/` : Treiber’s stack (TRB)
  - `ds/stacks_TSI/` : Interval timestamp-based stack (TSI)
  - `ds/stacks_CC/` : CC-Synch based stack (CC)
  - `ds/stacks_FC/` : Flat-combining based stack (FC)
  - `ds/stacks_EBF/` : Elimination-backoff stack (EBF)

The more detailed information of the following is in [setbench](https://gitlab.com/trbot86/setbench), the state of the art benchmark which we extend.

- `microbench/` : Benchmark top level source code that spawns threads and executes all algorithms.

  - `microbench/main.cpp` : benchmark main function that spawns threads and executes all algorithms.
  - `microbench/Makefile` : builds the microbenchmark binary
  - `bin` : contains the compiled binaries of each of the stack implementations.

- `common/` : Setbench shared infrastructure (pinning, stats, reclamation, utilities)

  - `common/recordmgr/` : memory reclamation implementations, for example DEBRA.

- `tools/` : Experiment runner + plotting framework

  - `tools/data_framework/run_experiment.py` : shared experiment harness used by our scripts.
  - plot utilities used by scripts in `sec_experiments/`

- `sec_experiments/` : Contains artifact scripts to reproduce paper figures

  - `run_quicktest.sh` : sanity check on small inputs before running the full set of experiments of the paper.
  - `reproduce_paper.sh` : reproduces all the figures in a given machine.
  - `experiment_reusability.py` : python script that can be extended to compare any stack implementation.
  - `plots/expected_plots/` : reference plots.
  - `plots/generated_plots/` : plots generated by your run.

- `lib/` : Contains different allocator static libraries.

### Evaluate throughput:

To quickly compile, run and see default results for throughput experiment follow these steps:

Assuming you are currently in sec_experiments, execute the following command:

`~$ ./setup_quicktest_inputs.sh`  
`~$ ./run_quicktest.sh`

### 🎉 What do above scripts for quick test do?

setup_quicktest_inputs.sh creates the inputs folder and the required .txt files to run run_quicktest.sh with small default values.
The names of these txt files depict the various run time parameters, for example reclaimer to use, thread sequence etc.

Following are the input files created by the `setup_quicktest_inputs.sh`

- _reclaimer.txt_ : reclaimation algorithm called debra.
- _steps.txt_ : comma separated list of number of steps each run needs to repeat. By default: 1
- _threadsequence.txt_ : comma separated list of thread sequence you want to run experiments with. This sequence becomes the X-axis for the generated throughput figures. By default: 1,14,28,40,56
- _workloadtype.txt_ : comma separated list of workload types. For eg., to evaluate with workload type of 50% inserts and 50% deletes enter 50 in workloadtype.txt. By defaults: 50

run_quicktest.sh will do the following:

1. Compile the benchmark with stack algorithms.
2. Run SEC, for a sequence of threads, for varying workloads with debra as reclaimer.
3. Produce figures in directory sec_setbench/sec_experiments/plots/generated_plots/quick_exp.

### Analyze generated figures:

You can find the figures in sec_setbench/sec_experiments/plots/generated_plots/quick_exp/ directory and analyse them.

- Each plot for throughput experiments follows a naming convention: throughput\_[total_machine_threads]\_[number of inserts]\_[number of deletes].png. For example, a plot showing throughput on 56 thread machine with 50% inserts and 50% deletes is named as: throughput_56_50_50.png.

The quick test section ends here.

## Recompiling the microbenchmark

If you modify any algorithm under `ds/stacks_*/` (e.g., SEC or baselines), recompile the benchmark:

```bash
cd sec_experiments
./compile.sh
```

Alternatively, rebuild manually:

```bash
cd microbench
make clean && make -j4 DATA_STRUCTURES=' Name of the algo'
```

If you change an algorithm under ds/stacks\_\*/, re-run compilation using one of the commands above.

## Adding a new stack algorithm

1. Create a new folder: `ds/stacks_MYALGO/`
2. Implement:
   - `adapter.h` (setbench adapter interface)
   - `stack_impl.h` (algorithm implementation)
3. Register the algorithm in the benchmark inside experiment.py.  
   -Locate define_experiment function.  
   -Find ds_algos and add your name in the list
4. Run the following commands to reproduce the figures in the paper and compare them with your own algorithm.

```bash
    cd sec_experiments
    ./reproduce_paper.sh
```

Note `reproduce_paper.sh` recompiles all algorithms and then runs the benchmark.

## Reusabilty
To facilitate extending this artifact (e.g., running on different hardware, testing new workloads, or adding new algorithms), we provide a flexible Python script ( which the tools/ directory of [setbench](https://gitlab.com/trbot86/setbench) already supports):
`experiment_reusability.py`.
1. How to run:
```bash
cd sec_experiments
python3 ../tools/data_framework/run_experiment.py experiment_reusability.py -crdp
```  
2. How to configure:
All settings are controlled by the EXPERIMENT_CONFIG dictionary at the top of experiment_reusability.py. You do not need to edit any logic code.

- A. To test with specific thread counts (e.g., for scaling analysis on different hardware), edit the thread_sequence list:
```python 
# Example: Run only on 1, 20, and 40 threads
"thread_sequence": [1, 20, 40]
```

- B. To test with different Push/Pop ratios, add new entries to the workloads list:

```python
"workloads": [
    {"i": 100, "d": 0},  # 100% Push only
    {"i": 0, "d": 0},    # 0% Updates (Read-Only)
]
```

- C. To benchmark a new algorithm, follow one of the already existing algorithms structure, compile it into the bin/ directory and add its name to the algorithms list in the experiment_reusability.py:
```python 
"algorithms": ['stacks_SEC', 'stacks_MYALGO'],
```

- D. Adjust trials to change the number of runs an algorithm executes for (e.g., for faster testing you may just want  to run a single trial), edit the trials list:
```python 
"trials": [1, 2, 3, 4, 5]
```

3. Output
The script automatically generates plots for the defined workloads and saves them to: sec_experiments/plots/generated_plots/custom_run
